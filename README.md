# Лабораторная CRM — Молекулярная селекция и генетика растений (Django 5.2)

Система для отслеживания образцов/проб (от исходного материала и выделения ДНК/РНК до ПЦР, Real-Time ПЦР, ФА и секвенирования), учёта движения реактивов/пластика/буферов, ведения журнала работ по дням и формирования квартальных отчётов.

Эта инструкция написана максимально просто и подробно, чтобы любой участник команды (даже без опыта программирования) мог скопировать команды и запустить проект на своём компьютере.

## Что реализовано по техническому заданию (п. 1–11 + уточнения)

1. **Выбор буферов из списка и управление позициями (п. 1)**:
   - В разделах **«Добавить буфер»** и **«Изменить Продукт на склад»** (если в строке «Внесение» выбран «Буфер») поле «Наименование продукта» превращается в выпадающий список из справочника **«Названия буферов»**.
   - В разделе **«Названия буферов»** администратор, руководитель или сотрудник склада может свободно добавлять новые названия буферов, менять порядок или удалять лишние позиции.
2. **Название раздела «Образец/Проба» (п. 2)**:
   - Раздел называется **«Образец/Проба»** (множественное число — **«Образцы/Пробы»**).
3. **Поле «Серия и номер» вместо старого «Уникальный код» (п. 3 и п. 4)**:
   - В списке и в карточке образца отображается поле **«Серия и номер»** (например, `QT №12*`), которое автоматически собирается из полей «Серия» и «Номер».
   - Комбинация «Серия + Номер» уникальна в базе данных: одна и та же серия не может иметь два одинаковых номера, а номера от 1 до 150 могут повторяться в разных сериях.
4. **Кнопка и заголовок «Добавить образец/ пробу» (п. 4)**:
   - Кнопка добавления и заголовок формы переименованы в **«Добавить образец/ пробу»**. Также доступна кнопка **«Добавить партию образцов»** для создания сразу диапазона номеров (например, с 1 по 96).
5. **Раздельный ввод «Исходный образец/проба» по серии и номеру + спецсимволы (п. 5 и уточнение)**:
   - Серия содержит от 2 до 5 символов.
   - Номер принимает числа от `1` до `150` и допускает спецсимволы `*`, `,`, `.`, `..`, `:` (например: `12*`, `5,2`, `10..15`, `48:`).
   - В форме образца блок **«Исходный образец/проба»** разделён на два поля: **«Исходный образец/проба — серия»** и **«Исходный образец/проба — номер»** (система сама находит исходную пробу по этим двум полям и связывает её с производной пробой ДНК/РНК/аликвотой).
   - В этапы задач добавлены: `Выделение ДНК/РНК`, `Постановка ПЦР`, `Real-Time ПЦР`, `Фрагментный анализ (ФА)`, `Секвенирование`, `Маркерный анализ`.
6. **Переименование в «Добавить общелабораторную работу» (п. 6)**:
   - В разделе «Приготовление и автоклавирование» кнопка и страница создания переименованы в **«Добавить общелабораторную работу»**.
7. **Поле «Тип задачи:» (п. 7)**:
   - Поле «Вид подготовки» переименовано в **«Тип задачи»** (`Приготовление реактива`, `Приготовление буфера`, `Автоклавирование расходников`).
8. **Поле «Добавить реактив:» (п. 8)**:
   - Поле «Готовая партия» переименовано в **«Добавить реактив»**.
9. **Количество от 0,1 до 100000 и выбор единицы измерения (п. 9)**:
   - Поле «Количество» проверяет диапазон от `0,1` до `100000`.
   - Добавлено поле **«Единица измерения»** с выбором из списка: `л`, `мл`, `мкл`, `кг`, `г`, `мкг`, `шт`, `упак`.
10. **Статистика по образцам/пробам в «Местах хранения» (п. 10)**:
    - На странице **«Места хранения»** напротив каждого холодильника/морозильника появилась ссылка **«Статистика проб (N) →»**, а сверху — кнопка **«Статистика по загруженным образцам/пробам»**.
    - На странице статистики видна разбивка проб по местам хранения, типам материала (ДНК, РНК, Растение и т.д.), проектам, сериям и полный список загруженных пробирок.
11. **Движение приготовленных реактивов, списание в Журнал работ / Задачи и страница «Наличие и баланс реактивов» (п. 11 и уточнение)**:
    - При сохранении записи в «Приготовление и автоклавирование» новая позиция сразу появляется в **«Поступления, резервы и расход»** и сразу доступна для расходования.
    - В разделе **«Журнал работ по дням»** прямо внутри формы записи за день добавлена таблица **«Списание пластика, реактивов, расходников и буферов в журнал работ»** — выбранные материалы автоматически списываются со склада и привязываются к задаче.
    - В разделе **«Задачи»** прямо внутри карточки задачи добавлена таблица **«Расход и резерв пластика, реактивов и буферов по задаче»**.
    - В разделе **«Продукты на складе»** добавлена кнопка **«Наличие и баланс реактивов (оповещения)»** (`/admin/lab/lot/stock-balance/`), где выводятся красные оповещения о заканчивающихся/просроченных реактивах и таблица баланса: *Поступило всего → Расход по задачам и журналу → Расход на новый реактив/буфер → В резерве → Свободный остаток на складе*.

## Шпаргалка по Git: как создать отдельную ветку для тестирования

Если вы хотите спокойно тестировать новую версию в отдельной ветке Git, не ломая основную ветку (`main`), выполните эти команды в терминале (в папке проекта):

### Вариант А. Если Git в папке проекта ЕЩЁ НЕ инициализирован

```bash
# 1. Инициализируем Git-репозиторий
git init

# 2. Создаём основную ветку main и делаем первый коммит
git checkout -b main
git add .
git commit -m "Базовая версия проекта Lab CRM"

# 3. Создаём и переключаемся на отдельную тестовую ветку (например, feature/tz-test)
git checkout -b feature/tz-test
```

### Вариант Б. Если Git-репозиторий УЖЕ есть

```bash
# 1. Проверяем, на какой ветке мы сейчас находимся
git status

# 2. Создаём новую ветку для тестирования ТЗ и сразу переключаемся на неё
git checkout -b feature/tz-test

# 3. Распакуйте файлы нового архива в папку проекта (с заменой файлов), затем посмотрите изменения:
git status

# 4. Сохраните изменения в тестовую ветку:
git add .
git commit -m "Реализация правок по ТЗ (п. 1-11) и настройка под локальный запуск/сервер"

# 5. Если проект подключён к GitHub / GitLab — отправьте тестовую ветку туда:
git push -u origin feature/tz-test
```

### Как переключаться между ветками и слить изменения после проверки

```bash
# Вернуться на старую ветку main (если нужно сравнить):
git checkout main

# Снова переключиться на тестовую ветку:
git checkout feature/tz-test

# Когда всё протестировали и хотите перенести изменения в основную ветку main:
git checkout main
git merge feature/tz-test
git push origin main
```

## Способ 1. Самый простой запуск на компьютере (БЕЗ Docker, за 1 минуту)

Этот способ идеален для тестирования на ноутбуке или ПК: база данных создастся автоматически в виде файла `db.sqlite3` прямо в папке проекта.

### Команды для Windows (PowerShell или Командная строка CMD)

Откройте терминал в папке `lab-crm` и выполните по очереди:

```powershell
# 1. Создаём виртуальное окружение Python
python -m venv .venv

# 2. Активируем виртуальное окружение
.venv\Scripts\activate

# 3. Устанавливаем библиотеки Django
pip install -r requirements.txt

# 4. Создаём таблицы базы данных и применяем все миграции
python manage.py migrate

# 5. Создаём роли, справочники буферов/холодильников и демо-пользователей
python manage.py bootstrap --demo

# 6. Запускаем сайт на компьютере
python manage.py runserver
```

### Команды для macOS и Linux

Откройте терминал в папке `lab-crm` и выполните по очереди:

```bash
# 1. Создаём виртуальное окружение Python
python3 -m venv .venv

# 2. Активируем виртуальное окружение
source .venv/bin/activate

# 3. Устанавливаем библиотеки Django
pip install -r requirements.txt

# 4. Создаём таблицы базы данных и применяем все миграции
python manage.py migrate

# 5. Создаём роли, справочники буферов/холодильников и демо-пользователей
python manage.py bootstrap --demo

# 6. Запускаем сайт на компьютере
python manage.py runserver
```

### Как войти в систему после запуска

1. Откройте браузер и перейдите по адресу: **http://127.0.0.1:8000/admin/**
2. Команда `python manage.py bootstrap --demo` уже создала готовые аккаунты для проверки всех ролей.
   **Пароль ко всем демо-аккаунтам одинаковый:** `LabCrmDemo2026!`
   - Логин `admin` — Полный доступ (Администратор + Руководитель) — **рекомендуется для первой проверки всех пунктов ТЗ**.
   - Логин `lead1` и `lead2` — Руководители (создание проектов/задач, проверка, допуск партий, отчёты).
   - Логин `warehouse1` — Склад (добавление пластика/реактивов/буферов, складские операции).
   - Логин `worker1` — Исполнитель (работа с задачами, журнал работ по дням, общелабораторные работы).

*(Если хотите создать своего собственного администратора со своим паролем, выполните в терминале: `python manage.py createsuperuser`)*

## Способ 2. Запуск на компьютере через Docker Desktop

Если вы хотите запустить проект на компьютере внутри Docker с базой данных PostgreSQL:

```bash
# 1. Запустить сборку и контейнеры в фоновом режиме (файл .env создавать не обязательно)
docker compose up --build -d

# 2. Создать демо-пользователей (admin / LabCrmDemo2026!) и справочники
docker compose exec web python manage.py bootstrap --demo

# 3. Посмотреть логи (если нужно проверить состояние)
docker compose logs -f web

# 4. Остановить контейнеры после работы
docker compose down
```

После запуска сайт также доступен по адресу: **http://127.0.0.1:8000/admin/**

## Автоматическая проверка проекта (автотесты)

В проект встроен набор автоматических тестов (`lab/tests.py`), который за пару секунд проверяет все 11 пунктов ТЗ и 14 правил лабораторного учёта.

Для запуска тестов:

```bash
# Если работаете локально без Docker:
python manage.py test

# Если работаете через Docker Desktop:
docker compose exec web python manage.py test
```

Если в конце выводится `OK`, значит вся логика проб, серий/номеров, буферов, склада, журнала работ и отчётов работает исправно.

## Способ 3. Перенос и запуск на боевом сервере (в будущем)

Когда вы протестируете проект на компьютере и арендуете сервер (VPS на Ubuntu/Debian с установленным Docker):

```bash
# 1. Клонируйте репозиторий на сервер и перейдите в папку
git clone <ссылка-на-ваш-репозиторий>
cd lab-crm

# 2. Создайте рабочий файл .env из шаблона
cp .env.example .env

# 3. Сгенерируйте надёжный секретный ключ и впишите его в .env (в поле DJANGO_SECRET_KEY)
python3 -c "import secrets; print(secrets.token_urlsafe(50))"

# 4. Отредактируйте .env (nano .env):
#    - DJANGO_ENV=production
#    - DJANGO_DEBUG=0
#    - ALLOWED_HOSTS=ваш-домен.ru,IP-вашего-сервера
#    - CSRF_TRUSTED_ORIGINS=https://ваш-домен.ru
#    - DB_ENGINE=postgresql
#    - Задайте сложные пароли в DB_PASSWORD и POSTGRES_ADMIN_PASSWORD

# 5. Запустите серверную связку (PostgreSQL + Gunicorn + планировщик + Nginx)
docker compose -f compose.yaml -f compose.prod.yaml up -d --build

# 6. Создайте учётную запись главного администратора
docker compose exec web python manage.py createsuperuser
```

### Полезные команды для обслуживания на сервере

```bash
# Сформировать квартальный отчёт вручную (например, за 3 квартал 2026 года):
docker compose exec web python manage.py quarter_report 2026 3

# Сделать резервную копию базы данных в папку backups/:
mkdir -p backups
docker compose exec -T db pg_dump -U postgres -d labcrm -Fc > backups/labcrm.dump

# Проверить восстановление резервной копии в отдельную тестовую базу:
docker compose exec db createdb -U postgres -O labcrm labcrm_restore_test
docker compose exec -T db pg_restore -U postgres -d labcrm_restore_test --no-owner < backups/labcrm.dump
```
