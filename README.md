# Лабораторная CRM — Молекулярная селекция и генетика растений (Django + Vue.js)

Система для отслеживания образцов/проб (от исходного материала и выделения ДНК/РНК до ПЦР, Real-Time ПЦР, ФА и секвенирования), учёта движения реактивов/пластика/буферов, ведения журнала работ по дням и формирования квартальных отчётов.

Эта инструкция написана максимально просто и подробно, чтобы любой участник команды (даже без опыта программирования) мог скопировать команды и запустить проект на своём компьютере.

## Исправления по результатам код-ревью безопасности (п. 1–8)

1. **Изоляция секретов СУБД от контейнеров приложения (`.env.db` и `.env.app`)**:
   - В `compose.yaml` переменные окружения разделены: контейнер `db` читает `.env.db` (с паролем суперпользователя `POSTGRES_PASSWORD`), а контейнеры `web` и `scheduler` читают только `.env.app` (с паролем ограниченной роли `labcrm` `NOSUPERUSER NOCREATEDB NOCREATEROLE`). Утечка окружения из Python-приложения больше не раскрывает пароль суперпользователя PostgreSQL.
2. **Полная поддержка HTTPS за прокси и `manage.py check --deploy`**:
   - В боевом режиме (`DEBUG=False`) по умолчанию включены `SESSION_COOKIE_SECURE=True`, `CSRF_COOKIE_SECURE=True`, `CSRF_COOKIE_HTTPONLY=True`, `SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")`, `CSRF_TRUSTED_ORIGINS`, `SECURE_HSTS_SECONDS=31536000`, `SECURE_HSTS_INCLUDE_SUBDOMAINS=True`, `SECURE_HSTS_PRELOAD=True`, `SECURE_SSL_REDIRECT=True`.
3. **Защита `/admin/login/` от перебора паролей (brute-force)**:
   - Встроен `AdminLoginRateLimitMiddleware` (`lab/security.py`), блокирующий вход с кодом `429 Too Many Requests` после 5 неудачных попыток за 15 минут (по IP и связке логин+IP), плюс автоматическая интеграция `django-axes` и `limit_req_zone` в `deploy/nginx.conf`.
4. **Перепроверка роли «Руководители» в момент `approve` / `return`**:
   - В `TaskEvent.clean()` при действиях `approve` и `return` дополнительно проверяется `lead(u)`, чтобы сотрудник, исключённый из группы «Руководители» после назначения ревьюером, не мог утвердить задачу.
5. **Запрет списания реактивов через `Preparation` в обход роли «Склад»**:
   - Создание и проведение `Preparation` (`complete()`), а также инлайны списания материалов закрыты проверкой `warehouse(user)` как в админке, так и на уровне модели (`Preparation.clean()` и `Preparation.complete()`).
6. **Защита от CSV-инъекций с учётом `\t`, `\r`, `\n`**:
   - Функция `safe_cell()` проверяет опасные префиксы `("=", "+", "-", "@", "\t", "\r", "\n")` до и после `.lstrip()`, не пропуская табуляции и переводы каретки.
7. **Независимый от `ALLOWED_HOSTS` и `SECURE_SSL_REDIRECT` Docker Healthcheck**:
   - `HealthcheckMiddleware` стоит первым в `MIDDLEWARE` и отвечает на `/healthz/` (проверяя `SELECT 1` в БД) до `SecurityMiddleware` и `CommonMiddleware`, а `127.0.0.1` и `localhost` всегда сохраняются в `ALLOWED_HOSTS`. Контейнер `web` остаётся `healthy` при любом боевом домене.
8. **Автотесты (`pytest` + `manage.py test`) и GitHub Actions CI**:
   - Добавлены `pytest.ini`, тесты на все сценарии приёмки и безопасности в `lab/tests.py`, а также пайплайн `.github/workflows/ci.yml` (проверяет миграции, `manage.py check --deploy --fail-level WARNING` и запускает `pytest`).

## Отдельная папка для визуализации (HTML + CSS + Vue.js)

В проекте выделена отдельная папка `frontend/`, чтобы вся кастомная вёрстка и визуализация на **Vue.js** лежали отдельно от серверного кода Django:

```text
lab-crm/
├── config/                  # Настройки Django, маршруты (urls.py), сервер (wsgi/asgi)
├── frontend/                # ОТДЕЛЬНАЯ ПАПКА ДЛЯ ВИЗУАЛИЗАЦИИ (HTML / CSS / Vue.js)
│   ├── templates/
│   │   └── frontend/
│   │       └── dashboard.html     # HTML-каркас дашборда на Vue.js
│   └── static/
│       ├── css/
│       │   └── dashboard.css      # Все стили визуализации (CSS)
│       └── js/
│           └── dashboard_app.js   # Приложение на Vue 3 (работает с JSON API)
├── lab/                     # Серверная логика CRM, модели БД, защита (security.py), API (api.py)
└── manage.py
```

* **Где посмотреть визуализацию на Vue.js:** после запуска сервера и входа в систему откройте **`http://127.0.0.1:8000/dashboard/`** (либо нажмите ссылку «Открыть сайт» в правом верхнем углу админки).
* **Откуда Vue.js берёт данные:** бэкенд отдаёт готовые JSON-данные по адресу **`/api/v1/dashboard/`** (`lab/api.py`).

## Что реализовано по техническому заданию (п. 1–11 + уточнения)

1. **Выбор буферов из списка и управление позициями (п. 1)**: в разделах «Добавить буфер» и «Изменить Продукт на склад» (если выбрано внесение «Буфер») поле «Наименование продукта» становится выпадающим списком из справочника «Названия буферов», где администратор/склад может добавлять и удалять позиции.
2. **Название раздела «Образец/Проба» (п. 2)**: раздел переименован в «Образец/Проба» («Образцы/Пробы»).
3. **Поле «Серия и номер» вместо «Уникальный код» (п. 3 и п. 4)**: автоматически собирается из полей «Серия» и «Номер» и защищено уникальным ограничением БД.
4. **Кнопка и заголовок «Добавить образец/ пробу» (п. 4)**: переименованы кнопка и заголовок страницы добавления.
5. **Раздельный ввод «Исходный образец/проба» по серии и номеру + спецсимволы (п. 5 и уточнение)**: серия 2–5 символов, номер 1–150 со спецсимволами `* , . .. :`. Исходная проба указывается двумя полями («серия» и «номер»). В этапы задач добавлены `Real-Time ПЦР`, `Фрагментный анализ (ФА)`, `Секвенирование`.
6. **Переименование в «Добавить общелабораторную работу» (п. 6)**: кнопка и заголовок формы в разделе «Приготовление и автоклавирование».
7. **Поле «Тип задачи:» (п. 7)**: вместо «Вид подготовки».
8. **Поле «Добавить реактив:» (п. 8)**: вместо «Готовая партия».
9. **Количество от 0,1 до 100000 и выбор единицы измерения (п. 9)**: валидация диапазона `0,1–100000` и выбор единицы (`л, мл, мкл, кг, г, мкг, шт, упак`).
10. **Статистика по образцам/пробам в «Местах хранения» (п. 10)**: переход со страницы «Места хранения» на страницу статистики загруженных проб по типам материала, проектам, сериям и списку пробирок.
11. **Движение реактивов, списание в Журнал работ / Задачи и страница «Наличие и баланс реактивов» (п. 11)**: автопроведение приготовленных партий в «Поступления, резервы и расход», таблицы списания внутри «Журнала работ по дням» и «Задач», страница `/admin/lab/lot/stock-balance/` с оповещениями и балансом.

## Шпаргалка по Git: как создать отдельную ветку для тестирования

Выполните эти команды в терминале (в папке проекта):

```bash
# 1. Создаём новую ветку для тестирования и сразу переключаемся на неё
git checkout -b feature/tz-test

# 2. Распакуйте файлы нового архива в папку проекта (с заменой файлов), затем проверьте список изменений:
git status

# 3. Сохраните изменения в тестовую ветку:
git add .
git commit -m "Реализация ТЗ (п. 1-11), закрытие 8 issues код-ревью, Vue.js и CI"

# 4. Отправьте тестовую ветку в GitHub:
git push -u origin feature/tz-test
```

Когда всё протестируете и захотите перенести изменения в основную ветку `main`:

```bash
git checkout main
git merge feature/tz-test
git push origin main
```

## Способ 1. Запуск на компьютере (БЕЗ Docker, на SQLite)

### Для macOS и Linux

```bash
# 1. Создаём виртуальное окружение (если ещё не создано)
python3 -m venv .venv

# 2. Активируем его (если в начале строки терминала ещё не написано (.venv))
source .venv/bin/activate

# 3. Устанавливаем зависимости
pip install -r requirements.txt

# 4. Применяем миграции базы данных
python manage.py migrate

# 5. Создаём роли, справочники и тестовых пользователей (пароль: LabCrmDemo2026!)
python manage.py bootstrap --demo

# 6. Запускаем сервер разработки
python manage.py runserver
```

### Для Windows (PowerShell или CMD)

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py bootstrap --demo
python manage.py runserver
```

После запуска откройте в браузере:
* Админка: **http://127.0.0.1:8000/admin/** (логин `admin`, пароль `LabCrmDemo2026!`)
* Дашборд Vue.js: **http://127.0.0.1:8000/dashboard/**
